# 知域 0.1.23 · 同步耗时与历史异常记录

## 本次变化

此前，运行状态能看到同步成功或失败，但不容易判断时间花在了导出、入库还是资料刷新上。旧异常回执中的未知字段也需要在读取时重新检查。

- “运行状态”新增三项同步耗时：导出等待、聊天入库、资料刷新。后台处理时间另列，包含服务准备、入库和刷新，不包含导出等待；几项时间不直接相加。
- 耗时由单调时钟实测。未启用或本轮无需执行的步骤单独标明；旧版本没有计时的记录显示“未记录”，不推算历史用时。
- 读取历史异常时，仅接受已知状态、原因和计数字段，重新生成处理建议。未知字段、原始报错和不符合格式的记录不会直接传到页面；成功导入的消息数量仍保留。
- 历史记录按实际时间排序，修正带不同时区的时间字符串可能排序错误的问题。同一轮的失败记录不会被较晚的普通回执覆盖成成功。
- 修正 MCP 对外版本号仍停在旧版的问题。打包前统一检查 Python、MCP、前端、桌面程序和锁文件的版本；缺失或不一致就停止，不生成混用版本的安装包。

每项功能分别提交。本次不新增常驻服务，不修改数据库结构、不扩展资料读取范围，也不额外保存聊天内容或按文件生成日志。沿用固定大小的精简回执与现有导出额度。

## 验证与使用边界

历史异常隔离回归 74 项通过，耗时与同步相关回归 126 项通过，版本检查、MCP 和安装资源回归 35 项通过。新增测试直接执行前端的耗时格式化代码，并通过隔离数据库运行后台入口；同时检查旧记录兼容、异常脱敏、失败状态和真实入库计数的保留。版本检查已在 Windows PowerShell 5.1 与当前 PowerShell 实际执行。

源码更新和安装包发布，不等于下一次真实夜间同步已经成功。WeFlow 是单独运行的第三方程序；已打开的旧实例不会因知域更新而自动加载新的调度代码，需要确认没有正在导出后安全重启。

安装不会默认启用定时同步，不附带 WeFlow、个人资料或聊天数据库。Windows 安装包仍未签名，另一台实体电脑上的完整安装体验仍待验证。
