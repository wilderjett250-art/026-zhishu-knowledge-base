# 新文件与运行诊断的实际边界

- 已登记为 `index` 的资料源，在下一次增量同步时会读取新增/变更文件；支持解析的文件建立正文索引，并额外做一次有界本地抽样，保存两级分类**建议**、分类规则版本、置信度与复核状态。原件不改动，抽样正文不写进运行日志。无法读取或发生变化时保留 `retry_required`，下一次同步重试。分类建议不是 Luna 结论，也不会自动升为 L2/L3 或发送到向量服务。
- `catalog` 资料源只登记路径，不读取正文，不能称为已按内容分类。整机 A 库及其分类台账是另一条链路；登记资料源的分类建议尚未自动合并进 A 库分类树。没有启用定时任务或运行同步时，新文件不会被自动发现。微信、聊天及远程 AI 仍按各自的授权开关处理。
- 新版同步与定时同步保留 `runs/diagnostics/{sync,scheduled-sync}/latest.json` 和最多 20 次有异常的 `recent-issues.json`。消息同步入口额外使用同目录的 `launcher-latest.json` 与 `launcher-recent-issues.json`（同样最多 20 轮），覆盖 Python 未能启动及本轮后台进程清理失败；两路按 `run_id` 合并显示。只写状态、阶段、数量、固定故障代码、允许的异常类型与处理建议，不写原文件路径、正文、请求、异常原文或令牌。旧版按次生成的日志不自动删除；Qdrant、API 与其他后台日志尚未统一限额，因此不能说全系统日志已全面治理。
- 桌面“运行状态”读取上述回执并显示最近异常的操作建议；“资料来源台账”按文件显示本地分类建议与失败处理方向。回执证明任务执行情况，不证明分类准确率；检索与向量效果仍需独立验收。
