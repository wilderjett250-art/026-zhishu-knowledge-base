# 知枢项目进度与主链路状态

更新时间：2026-09-18

## 先看结论

当前项目已经具备“电脑资料可建立索引、重要资料可处理、SQLite 与向量库可检索、Codex 可通过 MCP 查询”的核心能力。

自建 PKAS Agent 已从正常运行链路中停用。Codex 负责理解任务和决定是否检索，PKAS 负责资料发现、整理、索引和返回来源。

“工程机制完成度”和“电脑资料实际处理覆盖度”不是同一个百分比，必须分开看。

## 当前整体口径

- 核心知识底座可用度：约 **85%**。
- 全盘“知道每个文件大概是什么”的实际覆盖度：约 **0.34%**（按已形成处置结论计算）。
- 全盘 AI 速判实际覆盖度：约 **0.06%**。
- Codex 检索接入：约 **80%**，服务端已通，客户端重连验收待补。
- 面向他人安装使用的产品化：约 **60%～70%**。

整体不能简单说成 100%。现在最主要的剩余工作不是再增加一个 Agent，而是让全盘文件按预算分批完成 AI 速判，再把重要资料升级到摘要、全文、切块和向量层。

## 推荐的下一条主线

```text
目录台账
  → AI 速判“这是什么”
  → 按价值选择 L1 / L2 / L3
  → 重要资料解析、切块、全文与向量化
  → SQLite + Qdrant 混合检索
  → MCP 返回带来源的结果给 Codex
```

普通文件先完成目录和用途判断；项目说明、需求、设计文档、交付资料、客户记录等重要内容再做深度处理。这样既能让 Codex 知道电脑里有什么，也不会因为把数百万个低价值文件全部交给模型而拖慢系统或制造噪声。
