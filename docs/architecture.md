# 系统架构

## 一、总体分层

PKAS 采用一个逻辑知识库、多层物理存储的设计。

1. 数据源层：本地文件、项目仓库、聊天导出、网页、云端连接器和媒体资料。
2. 导入层：解析、哈希、去重、格式标准化、隐私分类和来源登记。
3. 存储层：原始资料、正式知识、自我模型、蒸馏数据和运行记录。
4. 索引层：全文索引、元数据过滤、语义索引、关系索引和重排序。
5. 服务层：搜索、读取、保存候选、批准、导入和导出接口。
6. 工作流层：可重复、可测试、可恢复的固定执行流程。
7. Agent 层：任务识别、上下文路由、工具选择、执行、验证和确认。
8. 接入层：Codex MCP、命令行、管理界面和后续外部应用。
9. 治理层：权限、隐私、审计、版本、备份、质量和评估。

## 二、核心数据流

资料进入系统后依次经过：

来源登记 → 原始保存 → 解析标准化 → 去重 → 分类 → 建立索引 → 检索使用 → 用户反馈 → 候选知识 → 审核提升

原始资料和派生资料使用不同标识，但通过来源关系连接。

## 三、知识域

### 工作域

业务逻辑、项目、代码、设备、服务器、研究、方案、决策、故障和经验。

### 自我域

个人事实、偏好、表达、价值判断、学习状态、行为倾向、反思和长期目标。

### 共享域

同时服务工作和自我理解的内容，例如工作方式、风险边界、沟通习惯和通用技能。

### 蒸馏域

经过筛选的问答、修正、决策、偏好、风格、学习轨迹和评估样本。

## 四、运行策略

- 普通业务任务优先检索工作域，并补充必要的共享工作偏好。
- 写作和表达任务优先检索自我域中的已确认风格样本。
- 学习任务同时检索主题知识和个人学习轨迹。
- 自我分析可以使用授权聊天作为证据，但候选结论需要时间跨度和反例检查。
- 检索只返回完成当前任务所需的少量内容，避免上下文膨胀。
- 高敏感内容只在明确授权的任务范围中返回。

## 五、工作流与 Agent

稳定任务采用工作流，包括资料导入、研究、学习、复盘、蒸馏候选生成和批准发布。

开放任务由一个总控 Agent 起步。总控 Agent 负责识别任务、选择知识域、调用工具和工作流、验证输出，并在必要位置请求确认。系统稳定后再按真实负载拆分工作、研究、学习、自我理解和蒸馏 Agent。

## 六、Codex 接入

Codex 通过项目级规则和本地 MCP 服务调用知识库能力。初始工具边界规划为：

- search_knowledge：按关键词、领域、时间、权限和状态检索。
- read_source：读取已授权的原始资料或正式知识。
- list_topics：浏览主题、项目和时间线。
- save_candidate：保存候选知识、反馈或蒸馏样本。
- approve_candidate：将经过确认的候选提升为正式内容。
- explain_provenance：返回结论对应的来源和推导关系。

所有写入工具保留审计记录，涉及长期自我模型和蒸馏提升时要求明确确认。
