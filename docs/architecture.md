# 知域核心架构

## 当前产品边界

知域当前做的是本地优先的个人知识底座：让人和 Codex 知道电脑里有什么、什么资料已经被理解到什么程度，并能用同一条检索链路找到可追溯的依据。

当前主产品**不把 PKAS 内置 Agent 或自动工作流当作必经环节**。历史上保留的 LangGraph、LangChain 和 DeepSeek Agent 模块默认关闭，正常 API 和 MCP 不会暴露它们；它们不是当前知识库、桌面端或 Codex 使用的前提。这样不会因为“自动总结”把未验证的助手表述混入事实库。

```text
本机文件 / 已授权聊天导出 / Obsidian 等目录
                │
                ▼
        A 库：目录索引（SQLite）
        路径、名称、类型、大小、时间、分类
                │  用户或规则选择处理深度
      ┌─────────┼──────────┬────────────┐
      ▼         ▼          ▼            ▼
     L0        L1          L2           L3
  仅目录    摘要/来源    正文+FTS    正文+FTS+向量
                │
                ▼
    SQLite 正式记录 + FTS5 全文索引
                │                    ┌─────────────┐
                └── 允许语义化 ────▶│ Qdrant 向量 │
                                     └─────────────┘
                │
                ▼
  Unified Search：目录 / FTS / 向量 / 过滤 / 重排 / 来源定位
                │
  ┌─────────────┼───────────────┬──────────────────┐
  ▼             ▼               ▼                  ▼
桌面控制台    Codex MCP      本机 HTTP API      RPA 回环桥
```

## 1. 资料层：原件不和索引混在一起

- **原始文件仍留在原位置。**A 库扫描只记录元数据，不读取正文、不搬运文件、不调用模型。
- 已明确确认进入 L1/L2/L3 的资料，会保留来源路径、内容哈希、时间、隐私级别和解析版本。对需要可恢复快照的授权导入，系统使用独立的哈希原件区；索引、摘要和向量都不是原件替代品。
- 聊天导出属于 `restricted` 资料。原始聊天、会话摘要、客户事实候选和普通文档保持分层，不能因为一个摘要就把推测当成事实。
- 密钥、私钥、证书和常见凭证文件按路径规则跳过；系统可记录“存在需人工处理的文件”，但不保存秘密值。

## 2. A 库：先回答“电脑里有什么”

A 库是独立 SQLite 文件目录索引，不是知识库正文，也不是向量库。每个文件至少记录：路径、父目录、扩展名、文件名、大小、修改时间、一级目录分组和确定性文件类别。

它的作用是让使用者先看清范围，再决定哪些类别值得深入。C 盘采用保守范围；其他本地固定盘可以建立目录清单，但系统目录、构建目录、软链接和敏感文件不会进入。任务可以暂停、恢复和增量续扫；暂停只影响指定任务，目录 MD 只概括元数据并明确标记“未读正文”。

### 资料来源不是绑死在一个软件上

在进入 A 库或正式资料库之前，知域先通过**资料接入适配器**识别来源。适配器只负责“怎样安全地把资料交给知域”，不改变后面的处理层级和检索规则。

- 本地文件和 Obsidian Vault 是内置来源；Obsidian 会跳过 `.obsidian`、`.trash` 和 `.git`。
- 聊天采用导出文件适配器。当前支持 WeFlow XLSX 与[ChatLab 兼容微信文件约定 v1](chatlab-wechat-format-v1.md)；ChatLab 文件不限定为某一个导出工具生成。
- WeFlow 的旧本机自动导出只能作为兼容模式，不能作为知域安装包的必备能力或跨电脑承诺。
- 探测只检查路径和目录元数据；读取内容必须走独立的只读检查与确认。适配器不读取密钥、不直接访问受保护数据库，也不执行用户下载的任意代码。

完整的扩展和审核边界见[资料接入适配器契约](import-provider-contract.md)。

## 3. 分类与四级处理：不是所有文件都应进向量库

| 层级 | 处理内容 | 可回答的问题 | 成本与边界 |
|---|---|---|---|
| L0 | 路径和分类 | 文件在哪里、属于什么 | 不读正文，不建向量 |
| L1 | 来源、有限摘录或目录摘要 | 大概是什么、是否值得继续看 | 仍不是完整全文证据 |
| L2 | 本地解析正文并写入 FTS5 | 文档具体写了什么 | 可全文检索，有定位 |
| L3 | L2 + Embedding + Qdrant | 相近意思、跨表述找资料 | 只对明确允许语义化的资料执行 |

确定性规则先根据文件类型、位置、体积、重复性和安全边界做初筛。需要内容判断时，可在用户明确允许后把**有限文字样本**交给 Luna 或 DeepSeek 做分类建议；模型输出必须通过本地来源、文件指纹和结构校验，不能自行升级成正式知识。用户可用预设处理方案或自定义规则决定最终 L0–L3。

## 4. 文档解析与切块：按结构，不盲目按字符数

- Word：标题、段落、表格、批注、页眉页脚和已有图片说明分别保留定位。
- Excel：工作表、表头、行、公式、批注、定义名称和图表说明分别解析；同表行切块会携带表头。
- PDF：优先读取原生文字块、页码和坐标；低文字页会被标记为需要视觉补全，而不是假装已读。
- PPT：幻灯片、标题、文本框、备注和可读取的对象说明分块。
- JSON/JSONL/聊天导出：消息时间、发言者、会话 ID、显式回复关联和非正文元数据保留为结构化字段；正文按会话、回复关系和时间边界切块，不把几行聊天臆测成“话题”。
- 代码：有效 Python 用 AST 顶级类/函数边界切块并保留缩进；语法错误或其他语言回退到可追溯的结构/行块，绝不把启发式边界标成 AST 事实。普通项目源码默认不应因为“存在”就批量进入 L3。

每份 Document、Block 和 Chunk 都有来源定位、解析器版本和质量提示。扫描件 OCR、图片语义理解和远程视觉服务是可选增强，不会在普通索引时静默运行。

## 5. SQLite、FTS5 与 Qdrant 的职责

```text
SQLite（正式记录）
  Source → Document → Block → Chunk
  隐私、版本、审计、处理层级、来源定位
  FTS5 全文索引

Qdrant（可重建派生索引）
  只保存 chunk_id、向量和最小过滤字段
  不保存正文、标题或本机绝对路径
```

SQLite 是“这份资料是否存在、是什么、来自哪里、正文和状态是什么”的正式来源。Qdrant 只负责相似语义候选；损坏或迁移后可由 SQLite 与授权原件重新生成，不能单独证明事实或任务完成。

## 6. 一条统一检索链路

桌面控制台、Codex MCP、HTTP API 和 RPA 本机桥都调用同一套 `unified_search` 规则：

1. 按领域、工作区、隐私、时间和处理层级过滤候选；
2. 目录 A 库负责文件名/路径定位，FTS5 负责精确全文召回；
3. 仅在有合格 L3 资料且用户选择语义检索时查询 Qdrant；
4. 用倒数排名融合合并全文和向量候选；复杂问题才允许重排；
5. 返回来源、定位、实际检索通道、降级原因和充分性提示。

因此“向量没有命中”不会等于“资料不存在”：系统会显示是否仅走全文、向量是否不可用、候选是否不足。带 `workspace_path` 的请求只会返回该项目及其子目录资料，防止另一个项目的“已完成”描述误召回。

## 7. Codex 与实在 Agent / RPA 的接入边界

Codex 通过本机 stdio MCP 使用检索、读文档、列来源、目录定位和已确认导入能力。MCP 和桌面端不共享“助手说已完成”作为事实；原始 Codex 回答不能替代文件、Git、测试、部署回执或用户验收。

实在 Agent 等 RPA 产品不能直接连接 SQLite。它们在**同一台电脑**上通过 `127.0.0.1` 的受限 HTTP 桥调用：

```text
实在 Agent HTTP 节点
  → 127.0.0.1 本机桥
  → Bearer Token + 回环来源校验 + 限流
  → unified_search / 受限消息台账
  → 脱敏、有界、无绝对路径的证据结果
```

桥默认关闭，不开放 SQL、任意表、任意路径、原文下载或局域网绑定。详细配置在 [RPA 本机桥说明](rpa-loopback-bridge.md)。如果 RPA 的 LLM 节点在云端，桥返回的检索证据会被该云端模型处理；这是 RPA 平台侧的数据边界，不是本机 SQLite 被公开访问。

## 8. 质量、可观测性与恢复

- A、B、AB 三种检索模式共用同一查询契约，管理台可以查看候选数、模式、降级和来源覆盖。
- 评测分为来源绑定银标和人工 0–3 级金标；没有人工判断的数据不能包装成正式准确率。
- 索引 Outbox 让正文/向量写入可恢复；向量事件只有实际覆盖完成后才确认。
- 恢复包以 SQLite 一致性快照、授权原件清单和哈希为核心，Qdrant 作为可重建项处理。密钥和令牌不进入恢复包或 Git。

## 9. 当前不属于主链路的能力

- 内置 LangGraph / LangChain / DeepSeek Agent：保留为历史兼容代码，默认关闭，不作为知识库运行条件。
- Codex 自动抓取和线程自动总结：默认关闭；只有用户在具体任务中明确授权后才可作为受控派生来源，且不把助手完成声明写入事实库。
- 图片 OCR、视觉理解、陌生电脑商业安装验收和自动发送微信：不是本轮核心闭环的一部分。

这套边界的目标很简单：先让资料可定位、可解释、可检索，再决定是否让模型参与理解或生成。模型可以提升分类和检索体验，但不能替代来源、权限、版本和完成证据。
