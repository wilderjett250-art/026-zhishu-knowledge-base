# 系统架构与安全边界

## 一、总体分层

PKAS 采用一个逻辑知识库、多层物理存储的设计。

1. 数据源层：本地文件、项目仓库、聊天导出、网页、云端连接器和媒体资料。
2. 导入层：解析路由、质量判定、结果融合、哈希、去重、隐私分类和来源登记。
3. 存储层：原始资料、正式知识、自我模型、蒸馏数据和运行记录。
4. 索引层：全文索引、元数据过滤、语义索引、关系索引和重排序。
5. 服务层：搜索、读取、保存候选、批准、导入和导出接口。
6. 工作流层：LangGraph 状态图承载可重复、可测试、可恢复的执行流程。
7. Agent 层：DeepSeek 负责规划和综合，LangChain Core 工具负责受控业务动作。
8. 接入层：Codex MCP、命令行、管理界面和后续外部应用。
9. 治理层：权限、隐私、审计、版本、备份、质量和评估。

WeFlow 属于数据源适配层。知枢读取 WeFlow 的导出记录索引，定位用户明确选择的现存 XLSX；它不读取数据库密钥、不直接打开 WCDB，也不依赖 HTTP API。原始 XLSX 保存为哈希快照，标准化消息进入客户消息表和独立全文索引。

后期研究方向记录在 `work-packages/WP-011-wechat-local-history-connector-research.md`：在用户自有账号和隔离测试环境中评估可维护的微信本地聊天连接器。该研究不改变当前生产边界；密钥获取、数据库连接和版本兼容逻辑必须封装在独立 Connector 中，PKAS 核心只接收规范化消息、来源回执和增量游标。第三方 DLL、反编译代码或许可证不明确的实现不得直接进入商业产品。

本地现成资料通过 SyncRoot 统一登记。`catalog` 模式只维护可搜索的文件目录，`index` 模式对安全且受支持的正文建立版本化索引。Codex 历史会话使用字节游标流式抽取每轮用户请求，明确丢弃最终回答；新任务通过 `agent-turn-complete` 通知即时写回用户请求，并继续调用原有桌面通知程序。逐回合写回仅执行本地脱敏、去重和索引，不触发模型。

## 二、核心数据流

资料进入系统后依次经过：

来源登记 → 原始精确解析 → 完整性判定 → 按需结构/视觉补全 → 结果融合 → 语义切块 → 去重 → 分类 → 建立索引 → 检索使用 → 用户反馈 → 候选知识 → 审核提升

原始资料和派生资料使用不同标识，但通过来源关系连接。

RAG 质量采用两级协议。`source-located-silver-v1` 固定验证绑定来源能否进入 Top5，并用不重排 Top20 支路定位候选、排序和重排阶段，不随题目是否升级成人工金标而消失；人工剔除题退出银标并产生补题缺口。`human-graded-scope-v1 / graded-scope-v2` 要求候选范围内每个 0–3 判断都来自用户，才报告正式 Precision、nDCG 和完整 Judgment Coverage。银标和人工金标不能互相冒充。

“全库可检索”不等于“全部进入同一个向量集合”。普通文档知识走 SQLite FTS5 + Qdrant 混合检索；Codex用户任务保留本地FTS但不生成向量；微信客户消息保存在独立restricted FTS并通过客户工具检索；百万级现成资料目录使用SQLite元数据定位；人工批准的长期知识作为单独正式层参与搜索。RAG管理台必须同时报告这些检索面，向量覆盖率只以符合Embedding策略的片段为分母。

知识细胞图不使用Qdrant顺序前N点。服务先无向量遍历全Collection元数据，再按`domain × source_type`平衡选样，最后只取样本向量做二维投影；这避免小类别在顺序抽样中完全消失。二维坐标和按字符长度缩放的细胞半径只用于观察，不参与检索评分。

Codex 每日收尾的数据流为：

任务通知 → 本地脱敏与入库 → 每日同步游标 → 按线程聚合 → 本地材料信号门控 → 每个有修改的线程创建一个后台任务 → LangGraph 检查点 → 只读检查授权工作区 → DeepSeek 整理开发状态 → 结构校验 → 带证据知识候选 → 后续检索

## 三、知识域

### 工作域

业务逻辑、项目、代码、设备、服务器、研究、方案、决策、故障和经验。

### 自我域

个人事实、偏好、表达、价值判断、学习状态、行为倾向、反思和长期目标。

### 共享域

同时服务工作和自我理解的内容，例如工作方式、风险边界、沟通习惯和通用技能。

### 蒸馏域

经过筛选的问答、修正、决策、偏好、风格、学习轨迹和评估样本。

## 四、运行策略

- 普通业务任务优先检索工作域，并补充必要的共享工作偏好。
- 写作和表达任务优先检索自我域中的已确认风格样本。
- 学习任务同时检索主题知识和个人学习轨迹。
- 自我分析可以使用授权聊天作为证据，但候选结论需要时间跨度和反例检查。
- 检索只返回完成当前任务所需的少量内容，避免上下文膨胀。
- 默认检索返回可定位的原始文档片段、Codex 用户任务和已审核知识项；未审核候选不会自动回流到 Agent 上下文，Codex 最终回答在采集层即被排除。
- 高敏感内容只在明确授权的任务范围中返回。

## 五、工作流与 Agent

稳定任务采用工作流，包括资料导入、研究、学习、复盘、蒸馏候选生成和批准发布。

开放任务由一个总控 Agent 起步。LangGraph 负责状态、节点、顺序、检查点和恢复；DeepSeek API 负责检索规划与跨证据综合；LangChain Core `StructuredTool` 负责知识检索、资料目录、项目状态和来源读取。当前采用“现场观察 → 初始检索 → 规划 → 工具执行 → 证据综合 → 候选写回”的混合模式。文件扫描、解析、去重、FTS5 检索、Git 现场读取和结构验证均在本地完成，不调用模型。

知识 Agent 使用六节点状态图，Codex 收尾使用三节点状态图。每个 Agent run 使用独立 `thread_id`，节点状态保存到 `data/index/langgraph-checkpoints.sqlite`。模型或工具节点失败后，运行记录保留 `next_nodes`；API、MCP 或后台任务可以从最后一个成功检查点继续。检查点只允许反序列化内置 JSON/MessagePack 类型，不启用 pickle 回退。

Codex 收尾采用每日批处理，不采用逐回合模型调用。系统持久化上次截止时间，只读取增量用户任务；同一线程的多个任务共享一个批次，普通问答和内部标题生成不进入 Agent 队列。用户任务不是完成证据；没有独立机器证据时，收尾结果只保留在 Agent 运行日志中，不写入知识候选。预算不足属于延期而不是失败，不增加重试次数；下一次每日同步继续处理。旧逐回合任务保留审计记录并标记为由每日批次取代，原始 Codex JSONL 不修改。

模型路由固定为：普通任务使用 `deepseek-v4-flash` 非思考模式；复杂任务显式使用 `deepseek-v4-pro` 思考模式。每次调用记录缓存命中、缓存未命中、输出、推理 Token 和估算费用。应用缓存由模型、提示词版本和输入哈希共同确定；临时网络或服务端错误最多重试一次，鉴权、参数和预算错误直接停止。

Prompt 采用注册表和独立版本号管理。规划、综合、收尾三个 Prompt 分别定义角色边界、输入不可信规则、证据等级、精确字段契约和输出预算。模型返回 JSON 后先执行语义字段校验；必填字段缺失时附带最小校验错误重试一次。失败调用同样计入 Token 与费用统计，避免预算只统计成功结果。每次调用及语义修复前重新计算剩余日预算，请求上限自动收紧到剩余额度，绝不通过提高预算完成任务。

## 六、文档解析架构

解析器是可替换适配器，不与数据库和检索器绑定：

1. Native Extractor 精确读取文本、代码、JSON/JSONL、CSV、HTML、PDF 文字块、DOCX、XLSX、PPTX 和 EML。
2. Quality Assessor 检查空文本、乱码替换字符、PDF 低文字页、Office 内嵌图片和图表。
3. Docling Extractor 作为显式启用的格式补全通道，统一输出 Markdown 语义块。
4. PaddleOCR Extractor 兼容 PaddleX `/layout-parsing`，只渲染并发送被判定为扫描件的 PDF 页或明确导入的图片。
5. Result Fusion 用页码和规范化内容去重，保留原生精确内容，并用视觉结果替换对应低质量页面。
6. Semantic Chunker 按标题、段落、表格、工作表、幻灯片、页码和坐标切块；超长块才使用带重叠的字符窗口。

每个来源在 `metadata_json` 中保存解析器列表、初始质量分、补全警告和块索引；`read_document` 返回该质量元数据。远程视觉通道默认关闭，`restricted` 资料默认禁止远程处理。普通同步与检索不调用文档模型，也不产生 Agent Token。

## 七、已实现技术栈

- Python 3.11、FastAPI、Typer 和 Pydantic：服务、命令行和参数契约。
- LangGraph 1.2：Agent 状态图、持久化检查点和失败恢复。
- LangChain Core 1.5：类型化业务工具和统一调用契约。
- LangGraph SQLite Checkpoint：每台个人电脑上的本地持久化运行状态。
- SQLite、FTS5 和本地文件系统：元数据、全文检索、证据状态和哈希原件库。
- Qdrant：本机可重建语义索引；不作为原文或完成状态的事实源。
- SiliconFlow Embedding API：只为允许远程处理且发生变化的片段生成向量。
- Model Context Protocol Python SDK v2：Codex stdio 工具服务。
- DeepSeek V4 API：自然语言检索规划、证据综合和 Codex 任务收尾；不部署本地模型。
- React 19、TypeScript 和 Vite：本地管理界面。
- PyMuPDF、python-docx、openpyxl、Beautiful Soup、OpenXML：本地精确资料解析。
- Docling 可选适配器、PaddleOCR-VL-1.6/PaddleX 服务适配器：复杂格式和扫描页补全。
- pytest、Pyright、Ruff 和 TypeScript build：自动化验证。

当前采用模块化单体，数据库是元数据和状态的正式来源，原件库是资料内容的正式来源。全文索引和 Qdrant 语义索引都可以重建。混合检索使用倒数排名融合合并 FTS 与向量候选；向量服务或云端 Embedding 不可用时降级为 FTS，并在语义能力已启用时报告异常。音频转写和其他外部连接器继续作为适配器加入，不替换当前正式来源。

灾难恢复采用独立恢复包而不是复制运行目录。主 SQLite 通过在线 Backup API 获得一致性快照，LangGraph 检查点独立校验，原文按清单逐文件哈希；Qdrant、日志和凭据不进包。恢复先落到旁路暂存目录，完成数据库、原文路径和 FTS 对账后原子落位，并默认禁用同步根。恢复包本身包含私人原文，复制出本机时必须使用 BitLocker 盘或其他加密介质；“不含 API 密钥”不等于“不含私人数据”。

## 八、Codex 接入

Codex 通过本地 MCP 服务调用知识库能力。当前工具边界为：

- search_knowledge：按关键词、领域、时间、权限和状态检索。
- read_document：读取已授权的原文和来源定位。
- list_sources：查看资料来源及其隐私属性。
- inspect_import_path：只读检查明确路径。
- import_confirmed_path：在用户确认后导入同一路径。
- list_sync_roots：查看持续资料源和同步覆盖率。
- register_sync_root：注册明确目录、模式、领域和隐私范围。
- scan_sync_root：对已完成一次性授权的资料源按指纹或字节游标增量同步。
- search_source_catalog：定位已盘点但尚未抽取正文的文件。
- prepare_agent_context：自动路由知识领域并准备证据。
- run_knowledge_agent：调用 DeepSeek 规划查询，执行本地检索并综合证据。
- run_codex_closeout：依据 Codex 任务记录和授权 Git 状态写入项目状态候选。
- get_agent_graph_status：查看检查点、待执行节点和可恢复状态。
- resume_agent_run：从最后一个成功检查点继续失败或中断的运行。
- list_agent_jobs：查看任务结束后等待整理的后台任务。
- get_agent_token_usage：查看当日 Token、缓存和费用审计。
- save_persona_candidate：保存待审核的个人观察。
- save_distillation_candidate：保存待审核的蒸馏样本。
- list_weflow_customers：列出已明确同步的微信客户。
- get_customer_timeline：读取授权客户的聊天时间线。
- search_customer_messages：检索微信客户聊天证据。
- prepare_customer_reply_context：组合客户档案、聊天和业务知识。
- save_customer_signal_candidate：保存待审核的客户业务信号。

所有长期写入保留审计记录。MCP 不提供批准画像或批准训练数据的工具，避免智能体自行提升关于用户的推断。

## 九、安全与恢复

- 每次导入都要求准确的绝对路径，拒绝磁盘根目录和知识系统自身目录。
- `.env`、私钥、证书和常见凭证文件按名称或后缀强制跳过。
- `restricted` 资料只有调用方显式授权时才能进入检索结果。
- 原始资料复制后再次计算 SHA-256，索引与原件分离。
- 候选画像和蒸馏样本必须由用户批准，并保留批准或驳回记录。
- WeFlow 接入只读取导出记录和用户明确勾选的 XLSX，不接触 `decryptKey` 或 WCDB。
- 微信聊天默认 `restricted`，检查令牌与文件哈希一致后才允许导入。
- 系统只准备客户回复草稿和证据，不直接调用微信发送动作。
- Codex 自动写回不保存推理、工具输出或附件二进制，常见凭证在落盘前脱敏。
- DeepSeek 只接收完成当前任务所需的脱敏片段和只读状态摘要，不接收整库数据或凭证。
- PaddleOCR 只在显式启用远程处理后接收低文字页面；restricted 资料需要独立授权开关。
- LangGraph 检查点使用独立 SQLite 文件和受限 MessagePack 反序列化，不使用 pickle 回退。
- 每次图执行都以 `tracing_context(enabled=False)` 强制关闭 LangSmith 外部追踪，不继承电脑的全局追踪开关。
- 项目现场检查只允许进入已经登记的 SyncRoot，且只执行 Git 只读命令。
- 每日恢复包默认保留同系列最新三版；索引损坏时从 SQLite 与原文重建，恢复副本必须先通过旁路演练再切换。
- 恢复包不含密钥但包含私人原文；离机保存和跨机传输必须依赖 BitLocker 或等效加密介质，系统不会把加密口令写入任务参数或清单。
