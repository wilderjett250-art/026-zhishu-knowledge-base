# 资料接入适配器契约

知域把“资料检索能力”和“资料从哪里来”分开。前者始终使用同一套来源追溯、SQLite/FTS、向量和混合检索；后者通过经过审查的资料接入适配器接入。

```text
用户自行选择的文件 / Vault / 聊天导出
                ↓
      适配器：探测 → 只读检查 → 明确确认
                ↓
   统一的来源、哈希快照、隐私和去重边界
                ↓
 SQLite / FTS5 / 可选 Qdrant → 桌面、MCP、HTTP
```

## 当前内置适配器

| 适配器 | 输入 | 是否随安装包可用 | 是否读取密钥或受保护数据库 |
| --- | --- | --- | --- |
| `local-files` | 用户选择的文件或目录 | 是 | 否 |
| `obsidian-vault` | 一个带 `.obsidian` 的 Vault | 是 | 否 |
| `chatlab-file` | ChatLab 兼容微信会话 JSON | 是 | 否 |
| `weflow-legacy-export` | 已存在的 WeFlow XLSX 和导出记录 | 仅导入器随产品可用；导出工具由用户另行安装 | 否 |

`weflow-legacy-export` 是兼容层，不是知域的跨电脑核心能力。它只能读取用户已经得到的导出记录和用户勾选的 XLSX。旧环境中的手动同步仅可作为本机兼容模式，不能据此称为一个可销售、可复制的微信数据库读取功能。

## 强制安全边界

每个适配器必须遵守以下规则：

1. **探测只读元数据。**只能判断路径、文件类型、目录标识或已安装状态；不读取聊天正文、数据库、密钥、Cookie 或令牌。
2. **内容检查独立。**读取内容前必须走显式的检查动作，并返回文件哈希或检查令牌。
3. **写入必须确认。**导入前再次核对检查令牌；源文件变化时拒绝导入，不静默替换。
4. **统一落库。**无论资料由哪个适配器提供，均保留来源、时间、内容哈希、隐私级别、处理状态与审计记录。
5. **聊天默认受限。**聊天导入默认 `restricted`；不能因为摘要或后续模型输出而降低权限。
6. **不加载任意插件代码。**当前注册表仅接受随知域源码或经过审核的安装包发布的适配器；不执行用户下载的 Python、JavaScript、批处理或外部命令。
7. **不处理受保护数据库。**适配器不得提取密钥、绕过访问控制、解密受保护数据库或模拟其他应用的登录态。

## 为同学使用的标准路径

1. 安装知域，先接入普通文件或 Obsidian Vault；这两项不依赖聊天工具。
2. 如需聊天资料，由对方自行选择并合法使用自己的导出工具。
3. 对方把导出结果保存为 WeFlow XLSX 或符合 [ChatLab 微信文件约定 v1](chatlab-wechat-format-v1.md) 的 JSON。
4. 在知域中执行“只读检查”，核对会话、数量和 `restricted` 范围。
5. 仅在确认后导入；后续检索仍走知域统一链路。

因此，某个外部导出器停止维护、版本不兼容或不允许再分发时，知域的文件、Obsidian、检索和已有导入资料不受影响。只需新增或更新对应的**文件格式适配器**，而不是改动整个知识库。

## 新适配器的评审要求

新增适配器前至少应提供：

- 稳定的 `provider_id`、输入格式版本和发布/再分发许可说明；
- `probe`、`inspect`、`import` 三个分离行为及失败原因；
- 合成测试资料，覆盖首次导入、重复导入、文件变化、无效格式、权限不足和受限资料；
- 证明不会返回绝对路径、聊天正文、密钥或令牌到不应看到它们的接口；
- 一台干净 Windows 环境的安装和文件导入验收。

适配器只负责把明确授权的资料规范地交给知域；它不替代外部软件的授权、版本兼容性或数据来源合法性。
