# Windows 夜间同步

知域使用当前 Windows 用户的计划任务 `PKAS-Knowledge-Sync`，默认每天 00:00 启动。任务只刷新已经登记且启用的本地文件/Obsidian 资料源；`catalog` 范围只更新文件台账，`index` 范围才解析正文并保存本地分类建议。它不会自动登记新磁盘、扫描 Codex 会话、调用 Luna，或启动向量 Embedding 队列。

## 安装版启用方式（0.1.21 起）

先打开知域，完成运行环境准备并在应用中登记需要更新的资料源。安装包已经包含同步脚本；不用另装 Python 或 Node。下面的 `<安装目录>` 是 `知域.exe` 所在位置，不是资料目录：

```powershell
# 只读检查，不注册任务、不修改资料。
& '<安装目录>\pkas-app\scripts\configure_scheduled_sync.ps1' -Action Status

# 明确授权后，启用已登记资料源的每日更新与开机补跑。
& '<安装目录>\pkas-app\scripts\configure_scheduled_sync.ps1' -Action EnableLocal -Approve

# 只移除该安装的主任务及一次性补跑任务，不删除资料。
& '<安装目录>\pkas-app\scripts\configure_scheduled_sync.ps1' -Action Disable -Approve
```

此入口只启用本地资料源更新，不替你启动 WeFlow、获取微信密钥或导出受保护数据库。已有授权的 WeFlow 自动导出链路仍需显式提供对应运行目录，见下面的配置说明；普通用户也可以把自行导出的 XLSX 作为聊天资料导入。WeFlow 不在知域安装包中。

脚本读取知域已经选择的数据位置，使用对应的 `runtime/python-env` 和安装内置的 Node；缺盘、运行环境缺失或任务名被另一份安装占用时拒绝操作，不创建另一份空知识库。任务配置更改前，只保存一份小型设置恢复点 `config/sync-task-recovery.json`，包含原策略字节和任务 XML，不复制数据库或聊天导出。失败时恢复原设置。安装版任务显式记录运行环境和数据路径，不依赖开发者机器上的虚拟环境。

## 错过一天后的开机补同步

每天 00:00 的正常任务保留。当前用户登录后，任务会在约一分钟内只读检查最近的每日同步进度；错过同步且开机未满 60 分钟时，安排固定名称 `PKAS-Knowledge-Sync-CatchUp` 的一次性任务，在剩余等待时间结束后执行。检查程序立即退出，不常驻等待、不每分钟扫描，也不为每次开机创建一个新任务。登录较晚、开机已经超过一小时的，直接补跑，不再从登录时多等一小时。睡眠错过的任务由 Windows 的 `StartWhenAvailable` 补触发，同样经过这项检查。

这是当前登录用户的任务，不保存 Windows 密码、不以 SYSTEM 身份读微信；电脑开机但用户尚未登录时，WeFlow 导出不能运行，登录后才进行补同步。本机采用登录检查加一次性任务，是因为 [Windows BootTrigger 文档](https://learn.microsoft.com/en-us/windows/win32/taskschd/boottrigger) 要求创建者属于管理员组，不应为了补同步提升整个微信进程的权限。计时使用 Windows `GetTickCount64` 的系统开机时长；混合关机/快速启动未重置系统开机时长时，以 Windows 报告的时长为准，不能声称等同每次物理按下电源的时间。

`data/config/nightly-sync.json` 只保存最近一次成功检查的时间、同轮标识与是否完成微信链路。不根据任务退出码、日志修改时间或本地目录扫描水位线猜测微信已经更新。成功导出（包括确认无新消息）且增量导入、进度及运行回执均正常后，才保存每日成功标记；失败或部分成功不会标记今日完成。有新增消息时重复触发会按消息去重，当日已经成功检查则跳过。跨午夜完成的轮次按开始时间计算，避免吞掉下一天的检查。主任务与一次性任务共享同安装范围的互斥锁，不会同时启动两轮导入。

数据盘低于 2 GiB 时，入口在启动 WeFlow 和打开 SQLite 之前停止并写入 `low_disk_space` 回执，不创建新的导出，也不推进水位线。空间不足并不能靠增加开机触发解决，必须先恢复足够空间。恢复后可手动启动 `PKAS-Knowledge-Sync` 重试；之后继续按每日任务和开机补跑执行。卸载同步任务会同时移除本安装的固定一次性任务，不删除资料。

如果单独授权了 WeFlow 每日导入，任务先检查授权，再等待当日 WeFlow 自动导出结束，最后只导入授权水位线以后的新导出。本机验证过的自动导出依赖单独改造的 WeFlow 运行环境；标准第三方版本尚未验收，知域仓库和安装包也不包含这份改造版。仅安装标准 WeFlow 时，应先手动导出 XLSX，再用知域的文件导入能力。已运行的 WeFlow 若仍是旧导出目录，计划任务会标记失败并继续处理已有导出，不会把“任务已启动”误报成微信已同步。WeFlow 导出报错或超时不阻断本地目录刷新，但本轮总体状态为失败。没有微信授权时不会启动 WeFlow。任务不会把微信原文写入运行回执。

本机单独改造的 WeFlow 日任务按本地日历时间检查，而不是从实际启动时间再隔 24 小时：错过零点后补跑，不会把第二天的检查也推迟到补跑时间。失败的自动导出每 30 分钟重试；进程意外中断留下的“运行中”状态在下次启动后最多 2 小时重试。夜间任务自己启动 WeFlow 时会等待一次重试结果，第二次失败或超过本轮 2 小时上限就退出并报告失败，避免后台开发进程整晚占用内存。导出目录无效或容量不足则直接报错，先处理路径或空间，再等下一轮。代码更新后必须退出旧 WeFlow 进程再启动，新调度器不会热更新到旧进程。

从 0.1.22 起，知域只在自行启动 WeFlow 前对齐这次导出任务的日程，保留成功游标，避免为了补跑重新导出所有历史消息。当日已检查或仍在运行的任务不重置，也不修改用户已经打开的 WeFlow。等待使用本轮开始时的日期边界，跨午夜完成的导出不会被丢掉。先给调度器一分钟启动余量；若旧式间隔任务的预计触发时间仍晚于本轮截止时间，记录 `weflow_schedule_not_due` 并停止无效等待。运行中的导出及失败后的重试不按这个预计时间提前中止。配置连续两分钟无法读取，或本轮自己启动的进程提前退出，也分别报告固定故障代码。发现已有导出后仍继续尝试入库，但导出故障不会因此被标成整轮成功。

这项日历调度改动属于本机 WeFlow 的独立适配，不随知域安装包分发。其他用户使用的第三方版本可能仍按间隔触发，应以实际任务状态核对；不能仅凭安装知域就宣称零点自动导出已经生效。

微信范围仅为 WeFlow XLSX 中的聊天消息行：保留消息原文、时间与来源，不扫描或复制旁边的图片和附件目录。为溯源保存的原始 XLSX 按内容哈希去重；相同文件重复导入不会多存一份，但新增消息后的新版 XLSX 会是新的快照。若 XLSX 自身嵌入了图片或附件二进制，本次拒绝导入该会话并报告失败，不会悄悄把媒体原件带入资料库。图片消息的文字占位仍可作为聊天记录保留。

知域自动导出的工作目录优先选空间充足的 I 盘，其次是 G 盘；均不可用时才考虑知识库所在的非系统盘，目录名固定为 `PKAS-WeFlow-Exports`。仅影响这个自动任务，不改 WeFlow 手动导出的全局目录。自动任务强制只写聊天 XLSX，不导出附件、图片或其他媒体原件；知域专属目录已有文件超过 4 GiB 时暂停下一轮导出，避免失败长期累积到占满整盘。正常入库后，仅在“导出目录确属知域专用、记录水位线已推进、数据库快照存在、库内原件字节与哈希均一致”的条件下，清理超过 7 天的旧导出副本；每个会话保留最近 2 份。失败、无法证明入库、目录不符或校验异常时不删文件，并在运行回执中记数量和处理方向。用户原有的手工或混合导出目录不参与自动清理。

其他资料源目前仍遵守原有授权：`catalog` 只记路径，`index` 才读取正文并建立全文记录。将它们改为自动 AI 摘要属于新的正文读取/模型处理权限，不会因微信同步授权而自动开启。

任务使用 `Interactive` 登录类型，不保存 Windows 密码：电脑需开机且当前用户已登录；睡眠错过时间时由任务计划程序在可运行时补跑。重复触发不会并发执行；计划任务自行启动的隐藏 WeFlow/Vite 进程在本轮结束后清理，不碰用户原本打开的实例。资料盘低于 2 GiB 空闲时暂停后续本地资料源；有待导入的 WeFlow XLSX 时，还会预留两倍候选文件大小。自动导出盘也需保留至少 2 GiB。空间不足不会推进微信导入水位线，回执标记失败，空间恢复后可重试。这个阈值不是磁盘用量上限：单次处理仍可能增长；旧恢复点与手工备份不会在夜间任务中自动删除。

运行中心的“资料库与恢复点占用”只读统计当前知识库数据目录内的数据库、向量索引、两类旧恢复点、历史备份和已入库的微信 XLSX 原文快照。其它盘上的受管导出副本与恢复点不在该统计内；它不会读取聊天内容或自动删除任何恢复点，迁移/删除须先逐份核实可恢复性。

查看 `Get-ScheduledTaskInfo -TaskName PKAS-Knowledge-Sync` 可以确认触发和退出码；任务内容和最近异常在 `data/runs/diagnostics/scheduled-sync/`，单独的本地刷新回执在 `data/runs/diagnostics/sync/`。回执只保留固定状态、数量与故障代码；不含文件正文、绝对路径或密钥。计划任务的“已注册”不等于当夜同步成功，应以同一轮回执和数据库资料源的 `last_scan_at` 核验。

## 消息同步的异常报告

消息同步的异常应由出错环节报告，不能只留一个退出码或把“没有成功读取消息”显示为“没有新消息”。当前源码覆盖以下环节：环境与授权检查、导出准备与等待、发现导出、XLSX 检查、消息入库、保存进度、清理导出副本、回收本轮后台进程、保存诊断文件。回执包含时间、同轮 `run_id`、失败环节、固定原因代码、数量、可安全公开的异常类型及处理建议。会话级入库失败按格式、授权边界、数据库或文件读写问题汇总数量，不复制会话名、聊天、异常原文或密钥到运行日志。

Python 尚未启动时，由不依赖 Python 的 PowerShell 入口保存 `launcher-latest.json` 与 `launcher-recent-issues.json`；Python worker 保存原有 `latest.json` 与 `recent-issues.json`。两路各只保留最近 20 轮异常，不按每天或每个会话新建文件。运行状态页面把同一 `run_id` 合并显示，后台进程退出失败记为警告，不抹掉本轮已入库消息数；下一轮成功不会清空最近异常。页面通过“查看同步异常与处理建议”展示失败阶段和处理方向。

读取历史记录时也会重新检查字段：只返回合法轮次、带时区的时间、已知状态、固定原因和允许的数值统计，不把旧记录里的任意附加字段、原始异常或自带建议直接交给页面。原因与处理建议从程序的固定表重新生成；不同时间偏移的记录按实际时间排序，同轮合并仍保留失败状态及已入库数量。损坏或超过大小上限的历史文件不会阻断其它有效回执。这是只读过滤，不迁移或重写已有日志。

升级后的定时回执另记录导出等待、聊天入库、本地资料刷新和 Python 后台处理的毫秒数，运行状态页会按阶段显示。导出等待使用 PowerShell 单调计时器，后台阶段使用 Python 单调计时器；电脑时钟校准不改变已经测量的时长。后台处理包含准备、入库和资料刷新，不含之前的导出等待，也不包含进程启动和最终回执落盘；它与各阶段不能简单相加。未启用微信或本轮无需刷新会单独标明，旧回执缺少计时字段则显示未记录，不补算历史。只增加少量允许的数值字段，仍覆盖固定回执文件，失败阶段也保留已测量时间与实际入库数量，不新增逐文件日志。

授权预检查只读指定数据目录的授权文件，不初始化数据库，也不读取聊天。微信同步未启用时，不因 WeFlow 环境缺失而阻断已授权的本地目录刷新。文件检查/导入失败不推进微信水位线；消息已提交、但进度保存失败时，报告实际新增数量并标记失败，重试仍会去重。消息已入库而副本清理失败时记录警告，保留入库结果。

如果数据盘不可用、写满或无日志写入权限，文件日志本身也可能无法保存；入口会输出脱敏的 `sync_receipt_failed` 信号，并以非零码退出供 Windows 任务计划程序检查，不能声称已保存日志。进程被强制终止或电脑断电也不可能保证即时写出异常，仍须结合任务状态和下一轮恢复检查。这是消息同步的局部治理，不代表其它模块日志已统一。

安装入口为 `scripts/install_scheduled_sync.ps1`，运行入口为 `scripts/run_scheduled_sync.ps1`。只需本地文件同步时显式传 `-LocalOnly`，无需安装 WeFlow；微信自动导出则需明确提供现存 `-WeFlowRoot`。两者不能同时指定。注册任务前必须通过本机自动启动授权策略。移除任务用 `scripts/uninstall_scheduled_sync.ps1`，不会删除知识库数据。正式数据的恢复必须先停止写入，再使用对应的已校验 SQLite 在线备份；不要把旧快照直接覆盖之后合法新增的资料。
