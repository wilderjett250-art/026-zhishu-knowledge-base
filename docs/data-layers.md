# 数据分层与验收契约

本项目不把“扫描到文件”误写成“已经理解了知识”。同一份资料会经历独立、可观察的层次；用户可以在每一层停止或继续。

```text
原文件（用户电脑）
        │ 只读定位
        ▼
L1 资料目录：路径、类型、大小、修改时间
        │ 按需解析
        ▼
L2 可检索正文：结构化文本、块、全文索引、来源定位
        │ 按需生成向量
        ▼
L3 语义索引：向量、模型版本、覆盖状态
        │ 统一检索
        ▼
A 精确 / B 语义 / AB 混合结果 + 引用与健康告警
```

## 每层解决什么问题

| 层 | 保存内容 | 适合回答 | 不代表 |
|---|---|---|---|
| L1 目录 | 原始路径和文件元数据 | “文件在哪里、有哪些候选资料” | 已读取正文或已经分类正确 |
| L2 正文 | 解析后的块与全文索引 | “文档里提到了什么、原文在哪一段” | 语义相近内容都能找到 |
| L3 向量 | 可重建向量和版本状态 | “换一种说法还能不能找到” | 向量服务一定在线或结果一定正确 |

原始文件始终留在用户指定的位置。目录、全文索引和向量都是可重建的派生数据；系统不能因为索引存在就移动、覆盖或删除原文件。

## 三种检索模式

- **A 精确检索**：文件名、路径、编号、报错、函数名与正文关键词。适合“某个合同”“某个型号”“报错原文”。
- **B 语义检索**：把查询与正文转换为同一语义表示，找同义表达和跨文档关联。适合“之前哪个方案解决过类似问题”。
- **AB 混合检索**：两路候选分别召回、去重、融合排序，最后返回可回到原文件的位置。

系统必须明确报告降级：向量服务不可用时，AB 只能退化成 A/全文检索，不能伪装成完整的语义检索。

## 写入与质量边界

1. 每个派生记录保存来源、时间、解析版本、隐私状态、置信度和复核状态。
2. 任何 AI 分类或摘要都必须有可核对的原文依据；无法核对时保留本地结果并标为待复核，不能覆盖为事实。
3. 同一文件内容未变化时不重复向量化；内容、切片规则或模型版本变化时生成新的索引版本。
4. 私密聊天、密钥、证书和系统敏感目录默认不进入普通检索。
5. 检索返回必须能定位来源；没有结果、覆盖不足、来源过期或通道降级时应明确提示。

## 最小验收清单

- 原文件哈希与导入时记录一致；派生过程不改动原文件。
- 任意 A、B、AB 结果都能返回来源标识和定位信息。
- 关闭向量服务后，精确/全文检索仍能工作，并显示语义通道已降级。
- 重复执行同一批导入不新增重复记录。
- 不同文件格式至少覆盖文本、PDF、Office 表格和代码；解析失败会记录原因而不是静默丢失。

这份文档定义的是公开框架的行为边界和验收口径，不包含任何个人资料、聊天导出、密钥、索引文件或本机运行配置。
